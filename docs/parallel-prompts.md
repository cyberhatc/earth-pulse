## Session C — done notes (accuracy review, 2026-11-09 10:12 IST)
- **Critical fix — `models/infer.py`:** `forecast_place` used a different variable order than `models/train.py` (`…solar_radiation,humidity,wind` vs `…humidity,wind,solar_radiation`). Because `RidgeRollout` flattens lag windows column-wise, every ridge forecast was wrong (e.g. cell 134: temperature 39.7 °C vs 26.1 °C, precipitation 32 736 mm vs 127 mm, NDVI −10.2 vs 0.98). Inference now reads the training order/`seq_len` from `models/artifacts/forecaster_meta.json`, prepares the model columns in that exact order, then subsets/reorders to the caller's requested variables. `models/train.py` now imports the canonical `VARIABLES` from `pipeline/export_store.py` to prevent drift.
- `engine/trends.py`: all-NaN series no longer emit a `nanmean` warning (returns flat slope); Mann–Kendall p-value now uses `norm.sf` to avoid underflow to exactly 0; documented the O(n²)/~1 MB cost at N≈500 (slope verified identical to `scipy.stats.theilslopes`).
- `engine/opposite.py`: simplified the convoluted `strength` expression; behaviour unchanged (strong ⇔ both MK-significant; at least one significant required unless disabled); verified no duplicate unordered pairs and all pairs have opposite-sign slopes.
- `models/forecast.py`: `RidgeRollout.fit` now raises a clear `ValueError` on non-finite X/Y instead of silently producing NaN weights/bands; intercept regularization exemption verified (lam=1e6 leaves intercept exactly at the target mean); `load()` closes the `.npz` handle.
- `models/project_maps.py`: documented that `slopes` must be per month (callers divide `slope_per_decade` by 120) and fixed the anchoring bug — the projection was anchored at the record mean without the `T-1 − mean_time` offset, misplacing values by up to ~0.3 NDVI / tens of mm of rain; now `mean + slope·((T-1−mean_time)+months_ahead)`.
- `pipeline/export_store.py`: `meta_json` is read with `.item()` rather than `str()` so a 1-element array can never leak `"['…']"` into `json.loads`.
- **Verified:** `python3 pipeline/run_pipeline.py --sample && python3 engine/run_engine.py && python3 models/train.py && EP_SAMPLE=data/samples/earth_pulse_sample.npz python3 -m pytest tests/ -q` → **37 passed, 2 warnings** (warnings are third-party deprecations). Engine emitted a benign `Mean of empty slice` warning while averaging fully masked (ocean/land) columns; handled by the existing `_nan_col_mean` fallback.
- **Concerns left (documented, not changed):** (a) pooled ridge training fills fully-masked columns (NDVI over ocean, SST/sea-level over land) with 0 via `fill_missing_linear`, so masked zeros can leak into cross-variable predictions — the API already drops those parameters per cell; (b) `pipeline.clean.rolling_mean` treats NaN as 0 (currently unused); (c) anomaly MAD floor is an absolute `1e-6`, so near-constant series can produce huge z-scores; (d) ridge bands assume independent 1-step errors (`√h`), which understates uncertainty for persistent autoregressive rollouts.
