# Earth Pulse — honest limitations

Read this before trusting any number the app shows. Every limitation below is
grounded in the code; citing it in the UI or demo is encouraged, not embarrassing.

## 1. The bundled demo data is synthetic — not real observations
- `data/samples/earth_pulse_sample.npz` is **generated by code**
  (`pipeline/run_pipeline.py --sample` → `pipeline/export_store.py`), deterministic
  and physically motivated, but it is **not measured data**.
- The trends are **baked in**: e.g., temperature warms, precipitation drifts, sea
  level rises at 3.4 mm/yr, SST resumes +0.10 °C/decade — by construction. Demo
  charts therefore *illustrate the app*, they do **not** quantify real climate.
- The store metadata says exactly this (`synthetic: true`,
  `provenance: "synthetic_demo"`), and the API repeats it in
  `data_coverage.synthetic_demo` + the explainer. Keep that label everywhere.

## 2. Demo grid resolution is very coarse
- The synthetic store is a **15° × 15°** grid: 10 latitudes (−60…75) × 24
  longitudes (−180…165) = **240 cells**, 498 months (**1985-01 → 2026-06**).
- Clicking New York and Cape Town 15° apart can hit the same cell. Real products
  would use 0.25°–1° resolution and a proper land/ocean mask.

## 3. Real-data record lengths differ per parameter — never claim "40 years" for everything
See `docs/data-sources.md` for the full check. Bottom line:
| Record | Honest start |
|---|---|
| MERRA-2 / POWER backbone | ~1980 / ~1981 |
| GISTEMP anomaly context | 1880 |
| Sea ice (NSIDC) | ~1979 |
| MODIS NDVI/LST/fire | ~2000 (**~25 y**) |
| SST (MUR GHRSST) | ~2002 |
| Sea-level altimetry | ~1993 |
The app trains multivariate models only on the **overlap period** and reports
per-parameter coverage instead of hiding the differences.

## 4. Forecast skill degrades with horizon
- Default horizon is **60 months**; uncertainty bands inflate with √h
  (residual σ·√h). Error bars grow, skill drops — the p10–p90 ribbon is a
  *probabilistic outlook*, not a guarantee.
- The bands are calibrated on the data they were trained on (backtest PICP). The
  real-POWER store has a genuine rolling-origin backtest, but it still covers one
  region/horizon; the synthetic demo's PICP says nothing about real-world
  coverage.
- Regime shifts (volcanic eruptions, ENSO flips, abrupt land-use change) are
  outside the training distribution; the model cannot anticipate them.

## 5. Regional teleconnections are unmodeled
- Features are per-parameter lags + month harmonics (sin/cos) + a year index.
  ENSO, monsoon dynamics, ocean–atmosphere coupling and other teleconnections
  have **no explicit representation** — "opposite trends" explanations are
  generic, not mechanism-specific.

## 6. Opposite Trend Detector is statistical, not causal
- It pairs neighbouring cells whose slopes have opposite signs and rates the
  pair strong only when both Mann–Kendall tests are significant
  (`engine/opposite.py`). It is a *detective lead*, not evidence of cause; it
  says nothing about which mechanism (land use, irrigation, orography, local
  pollution) drives the divergence.

## 7. Climate twins are an arbitrary clustering
- K-Means, k=8 (`configs/model.yaml`), z-scored multivariate cell features with a
  fixed seed. Different k reassigns cells; clusters are a *didactic similarity
  view*, not a recognized climate classification.

## 8. Synthetic store ignores geography
- No land/ocean/coast mask: SST and sea level are shown for inland cells
  (symbolic). No elevation, land cover or irrigation variables per cell.

## 9. Narration: local LLM is optional, guarded, and small
- `POST /chat` uses a **local Ollama** model (default `qwen2.5:1.5b`) when it is
  running. `/place` explanations stay **templated** by default; set
  `EP_EXPLAIN_LLM=1` to use Ollama there too (slower). If Ollama is unreachable,
  both endpoints return deterministic templated prose instead of failing.
- **HF Inference** (`HF_TOKEN`) is an optional alternate backend. The **Gemini**
  backend is planned and **not yet wired** (`api/services/explainer.py`; key
  already plumbed through `docker-compose.yml`).
- The LLM only re-words backend facts; it never computes a statistic. A 1.5B
  local model can still misread statistics, so post-generation guards reject
  certainty claims, p-values framed as probabilities/confidence, p10–p90 bands
  described as 10–90% chances, non-significant trends called significant, and
  any number absent from the facts. Rejected drafts are replaced with
  `templated-guard` prose and report `guard_reason` / `guard_numbers`.

## 10. Deployment/operational limits
- API is read-mostly (`GET` plus `POST /explain` and `POST /chat`), in-process
  rate limiting; no auth — built for demo scale, not hostile public traffic.
- Free tiers sleep (Render) or force cold rebuilds (HF Spaces); first request may
  be slow.
- The web map pulls OSM/GIBS tiles from the network; low-bandwidth mode strips
  imagery but MapLibre still needs connectivity for the base map.
- Watchlist/alerts live in `localStorage` only — no accounts, no server-side
  notification transport.

## 11. What the demo must never be claimed to be
- A measurements product, an operational forecast, a peer-reviewed study, or an
  attribution tool. It is an **open educational explorer** with honest labels:
  *Observed* (real sources, when wired) · *Model forecast (p10–p90)* ·
  *Synthetic demo* · *AI-generated scenario* (disabled by default).
